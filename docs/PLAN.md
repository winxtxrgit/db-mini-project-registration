# แผนออกแบบระบบใหม่: 3 บทบาท (นักศึกษา / ฝ่ายทะเบียน / อาจารย์ผู้จัดตาราง)

อัปเดต 22 พ.ย. 2569 · รอบนี้ทำเฉพาะตัวระบบ (ฐานข้อมูล กฎ สิทธิ์) ส่วน UX/UI จะออกแบบใหม่ทีหลัง หน้าเว็บรอบนี้จึงทำแบบเรียบง่ายพอใช้งานและทดสอบได้

## 1. หลักการ

| เรื่อง | อยู่ที่ไหน | เหตุผล |
|---|---|---|
| กฎทางธุรกิจ (เวลาชน ที่นั่ง โควตา หน่วยกิต ช่วงลงทะเบียน ห้องซ้ำ อาจารย์ซ้ำ) | trigger ในฐานข้อมูล | ไม่ว่าจะแก้ข้อมูลจากหน้าเว็บหรือจาก sqlite3 ตรงๆ ก็โดนตรวจเหมือนกัน (เป็นจุดเด่นของงานวิชาฐานข้อมูล) |
| สิทธิ์ว่าใครทำอะไรได้ (นักศึกษาแก้ได้เฉพาะของตัวเอง ฯลฯ) | แอป Flask | trigger ไม่รู้ว่าใคร login อยู่ |
| ใครเป็นคนทำรายการ | ตาราง `app_session` 1 แถว ที่แอปเขียนในทุก transaction | ให้ trigger รู้บทบาทของผู้ทำรายการ (ใช้กับกฎช่วงลงทะเบียน และบันทึกลง log) ถ้าไม่มีแถว = รันจาก sqlite3 โดยตรง (ระบบ) |

## 3. เปลี่ยนแปลงฐานข้อมูล

**ตารางใหม่ 3 ตาราง (รวมเป็น 21)**
- `app_user` บัญชีผู้ใช้: username, password_hash, role (`student`/`admin`/`scheduler`), ผูก `student_id` (ถ้าเป็นนักศึกษา) หรือ `instructor_id` (ถ้าเป็นอาจารย์ผู้จัดตาราง), is_active
- `app_session` ผู้ทำรายการปัจจุบัน (มีได้แถวเดียว)
- `schedule_log` ประวัติการแก้เวลาเรียน เวลาสอบ อาจารย์ผู้สอน (บันทึกด้วย trigger)

**คอลัมน์ใหม่**
- `term.reg_open_at`, `term.reg_close_at` ช่วงลงทะเบียน · `term.max_credits` หน่วยกิตสูงสุดต่อภาค (ค่าเริ่ม 22)
- `registration_log.actor_user_id` ใครเป็นคนทำ (NULL = ระบบ / sqlite3)

**กฎใหม่ใน trigger**
1. นักศึกษาลง/ถอน/เข้าคิวได้เฉพาะในช่วงลงทะเบียน (admin ไม่ติดกฎนี้)
2. หน่วยกิตรวมในภาคต้องไม่เกิน `max_credits`
3. เข้าคิวได้เฉพาะคนที่มีสิทธิ์ลงวิชานั้นจริง (ผ่านวิชาบังคับก่อน ยังไม่เคยผ่าน)
4. ลดจำนวนรับหรือโควตาให้ต่ำกว่าคนที่ลงอยู่แล้วไม่ได้
5. เวลาเรียน: ห้องซ้ำไม่ได้ (ยกเว้นกลุ่มของวิชาเดียวกันเรียนรวม) · อาจารย์สอนสองที่พร้อมกันไม่ได้ · ย้ายคาบไปชนกับวิชาอื่นของนักศึกษาที่ลงแล้วไม่ได้
6. เวลาสอบ: ห้องสอบซ้ำไม่ได้ · ห้องต้องจุพอ (ถ้ารู้ความจุ) · นักศึกษาที่ลงแล้วต้องไม่สอบสองวิชาพร้อมกัน
7. มอบหมายอาจารย์ให้กลุ่มที่เวลาชนกับที่อาจารย์สอนอยู่ไม่ได้

**แก้บั๊กที่มีอยู่เดิม**
- เดิมถ้าคนแรกในคิวไม่มีสิทธิ์ลง (เช่น ยังไม่ผ่านวิชาบังคับก่อน) การเลื่อนคิวจะ error ทำให้คนอื่น "ถอนไม่ได้" แก้โดยให้ `v_waitlist_rank` คำนวณคอลัมน์ `eligible` (ไม่ชน + มีที่ + หน่วยกิตไม่เกิน + ผ่านวิชาบังคับก่อน) และเลื่อนเฉพาะคนที่ `eligible`
- เดิมเพิ่มที่นั่งแล้วคิวไม่ขยับ เพิ่ม view `v_waitlist_next` และปุ่ม "เลื่อนคิว" ของ admin

## 4. รายงานและ demo ใหม่
- R7 หน่วยกิตที่ลงของแต่ละคน เทียบเพดาน · R8 การใช้ห้องเรียน/ห้องสอบ · R9 ภาระสอนของอาจารย์

- D3 เดิม (ใส่วันสอบสมมุติที่ชน) ต้องเขียนใหม่ เพราะกฎจัดสอบใหม่จะกันตั้งแต่ตอนใส่วันสอบ

## 5. หน้าเว็บ (เรียบง่าย ยังไม่เน้น UX)
- login / logout · รหัสผ่านเก็บเป็น hash · มี CSRF token ในทุกฟอร์ม
- นักศึกษา: `/me`
- ฝ่ายทะเบียน: `/admin` (ภาพรวม), ภาคเรียน, กลุ่มเรียนและโควตา, คิว, นักศึกษา, บัญชีผู้ใช้, ประวัติ
- ผู้จัดตาราง: `/schedule` (กลุ่มเรียน เวลาเรียน เวลาสอบ อาจารย์), ห้อง, ประวัติการแก้ตาราง
- บัญชีทดสอบอยู่ใน `seed.sql`
