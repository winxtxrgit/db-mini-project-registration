# สรุปงาน ณ 22 พ.ย. 2569

ระบบวางแผนและตรวจสอบการลงทะเบียนตามแผนการเรียน (Study Plan–Aware Registration System) · SQLite + Flask

## 1. สิ่งที่ทำเสร็จแล้ว

**ขอบเขต**
- ตัดงานกลับมาเหลือระบบลงทะเบียนชุดเดิม แล้วต่อยอดเป็นระบบ 3 บทบาท ได้แก่ นักศึกษา ฝ่ายทะเบียน (admin) และอาจารย์ผู้จัดตาราง (scheduler)
- งานรุ่น v2 เดิมเก็บไว้ใน `archive/v2/`

**ฐานข้อมูล** (`schema.sql`, `seed.sql`)
- 21 ตาราง · 14 view · 22 trigger
- กฎทางธุรกิจทั้งหมดอยู่ใน trigger จึงโดนตรวจเหมือนกันไม่ว่าจะแก้ข้อมูลจากเว็บหรือจาก sqlite3:
  - ช่วงลงทะเบียน (ใช้กับนักศึกษาเท่านั้น)
  - หน่วยกิตสูงสุดต่อภาค
  - วิชาบังคับก่อน
  - เวลาเรียนชน · เวลาสอบชน
  - ที่นั่งและโควตาหลักสูตร
  - ห้องเรียน/ห้องสอบซ้ำ · อาจารย์สอนชน · ความจุห้องสอบ
- ใครเป็นคนทำรายการ: แอปเขียนผู้ใช้ลง `app_session` ในทุก transaction แล้ว trigger อ่านบทบาทจาก view `v_actor` และบันทึกลง `registration_log` / `schedule_log`
- แก้บั๊กคิวสำรอง: เดิมถ้าคนแรกในคิวไม่มีสิทธิ์ลง จะทำให้คนอื่นถอนไม่ได้ ตอนนี้เลื่อนคิวเฉพาะคนที่ `eligible` (`v_waitlist_rank`, `v_waitlist_next`)

**สาธิตและรายงาน**
- `demo.sql`: D1–D18 รันแล้วได้ error ตามที่ตั้งใจ 13 ข้อ
- `queries.sql`: รายงาน R1–R9

**หน้าเว็บ** (`web/`, Flask)
- login (รหัสผ่านเก็บเป็น hash) · CSRF ทุกฟอร์ม · กันสิทธิ์ตามบทบาท
- นักศึกษา `/me` · ฝ่ายทะเบียน `/admin` · ผู้จัดตาราง `/schedule`
- ชุดทดสอบ `web/test_app.py` ผ่าน 30/30 (เพิ่ม 5 ข้อสำหรับหน้าเว็บที่ออกแบบใหม่)

**เอกสารและไฟล์ส่งงาน**
- ER diagram 21 ตาราง (`Diagrams/registration-er.drawio`, `.png`) ตรวจคอลัมน์ PK/FK/UQ ครบแล้ว

## 3. วิธีรัน

```bash
sqlite3 :memory: ".read run.sql"           # สร้างฐาน + demo + รายงาน
pip install flask && python web/app.py     # เปิด http://127.0.0.1:5000
python -m unittest discover -s web -v      # ชุดทดสอบ
```

บัญชีทดสอบอยู่ใน comment ของ `seed.sql`
